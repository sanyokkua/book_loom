# AI agent setup

How the repository is arranged so Claude Code, Codex and other agents read the same rules, and how work is planned
with OpenSpec.

## One source of truth

| File | Role |
|---|---|
| [`AGENTS.md`](../../AGENTS.md) | the operating manual, binding for every agent: what the app is, current state, commands, Definition of Done, module table, non-negotiables with their enforcement, planning, git protocol, known traps |
| [`CLAUDE.md`](../../CLAUDE.md) | one `@AGENTS.md` import plus a note. It holds no rules; new rules go in `AGENTS.md` so two copies cannot drift |
| `.claude/rules/*.md` | detailed rules scoped by path (14 files, below) |
| `.agents/skills/` | skills, one copy |
| `.claude/agents/*.md` | sub-agent definitions (source) |
| `.codex/agents/*.toml` | generated Codex versions of those agents |

`scripts/sync-agent-files.py` keeps the entry points consistent and `--check` fails on drift. It is run by the
pre-push hook and by the CI quality job.

### What the sync script does

| Mode | Effect |
|---|---|
| (no flag) | report only |
| `--apply` | create links and regenerate the mirrors (the `.codex/agents/*.toml` files, headed "GENERATED by scripts/sync-agent-files.py, do not edit") |
| `--check` | assert and exit 1 on drift: used by pre-push and CI |
| `--migrate` | one-time move of `.claude/skills` to `.agents/skills` |

Options come from `.agentsync.json` (all optional; defaults: `copilot` true, `gemini` false, `codex` true,
`max_lines` 200 warn, `hard_lines` 250 fail). This repository sets `"copilot": false`. The script also checks that
`.codex/skills` is absent and warns or fails when `AGENTS.md` grows past the line limits. Edit the `.claude/agents`
file, then run `--apply`; never edit a `.toml` mirror.

## OpenSpec workflow

OpenSpec lives in `openspec/`: `config.yaml` (project context, authoritative documents, the module graph, the
non-negotiable invariants, authoring rules that steer generated artifacts), `specs/` and `changes/`.

| Folder | Holds |
|---|---|
| `openspec/specs/<capability>/spec.md` | the ledger of what is built; 17 capabilities (`app-shell`, `book-brief`, `book-import`, `document-round-trip`, `export`, `glossary`, `inference`, `llm-provider`, `local-storage`, `localization`, `notifications`, `quality-gates`, `resume`, `review-queue`, `settings`, `theming`, `translation-pipeline`) |
| `openspec/changes/<name>/` | the unit of work: `proposal.md`, `design.md` when warranted, `specs/` (delta requirements), `tasks.md` |
| `openspec/changes/archive/<date>-<name>/` | finished changes (12 archived) |

Current state: one open change, `redesign-translation-pipeline` (built; the owner's checks and the archive remain),
with an `owner-checklist.md`.

The loop is propose, validate, apply, archive:

1. **Propose** (`/opsx:propose`): create the change and its artifacts. A change is small: a brief of at most one page,
   at most about 10 tasks (a large change may group them), a sentence-level checkbox per task.
2. **Apply** (`/opsx:apply`): implement the tasks. The acceptance test is seen red before the implementation, then
   green, then the app is run by hand. A checkbox is a claim, the test is the evidence.
3. **Archive** (`/opsx:archive`): the change moves to `archive/` and its delta specs fold into `openspec/specs/`.
4. `/opsx:explore` is for thinking before or during a change; `/opsx:update` revises a change's planning artifacts
   without touching code; `/opsx:sync` merges delta specs into the main specs without archiving.

`/opsx:*` is available, not required: `AGENTS.md` says a change gets an OpenSpec proposal when the owner wants one. No
task ledger is kept after a change ships. Never edit an archived change.

## Where decisions and specs go

| Item | Place |
|---|---|
| A decision that is costly to reverse | an ADR in [`docs/spec_baseline/adr/`](../spec_baseline/adr/), numbered `ADR-NNNN`, naming what would falsify it; format in `docs/spec_baseline/implementation_plan/04_ADR_FORMAT.md` and the `adr-authoring` skill |
| A clause in the original specification that the code shows wrong | edit the clause in `docs/spec_baseline/specification/` in the same change |
| New behavioural requirements | the change's `specs/` folder, folded into `openspec/specs/` on archive |
| Backlog items | `docs/spec_baseline/implementation_plan/CHANGE_BACKLOG.md` |
| Work found after a plan was fixed | the archived change's `additional-work.md` (see `AGENTS.md`), IDs unchanged |

## Git protocol for agents

`master` is protected: never develop on it or merge into it; final review and merge belong to the owner. Work on
`feature/<slug>`, branch each task as `feature/<slug>--<task>`, commit each task there, squash-merge it into its parent
feature branch and delete the task branch. Never `--no-verify`, never force-push. Stop and ask only to resolve an
ambiguous spec (propose a default), when the gate is red twice for the same cause, or before anything irreversible
(merge to `master`, tag, publish, delete outside the repo).
