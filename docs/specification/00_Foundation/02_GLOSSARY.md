# Glossary

This glossary defines the vocabulary used across the specification. Terms are the canonical names; requirement and story
text must use them consistently.

## document-model-terms {#document-model-terms}

| Term                         | Definition                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
|------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Segment                      | The smallest translatable unit of text extracted from the document — typically one paragraph, heading, list item, table cell, or verse line. Each segment has a stable id, a source-language string, an optional target string, a status, and a source hash.                                                                                                                                                                                                                                                                                                         |
| Chunk                        | A working batch of one or more whole segments packed together up to the token budget and sent to the model in a single translate call. Segments are never split across chunks; oversized single paragraphs are sentence-split only on overflow.                                                                                                                                                                                                                                                                                                                      |
| Skeleton                     | The full structural representation of the document (element tree, attributes, images, fonts, IDs, order) with translatable text nodes removed and replaced by segment references. The skeleton is never sent to the model and is never regenerated; only its text nodes change. This is what makes structure preservation correct by construction.                                                                                                                                                                                                                   |
| Inline masking / placeholder | The replacement of inline markup, locked glossary terms that carry a target, URLs, inline code and inline MathML (DD-49), and, under the Keep foreign-passage policy, a kept foreign inline run, with opaque placeholder tokens of the form `⟦gN⟧` before translation, so the model cannot alter them. No numeral is masked in this build — every numeral, standalone or in prose, stays translatable (owner decision D-7). After translation the placeholders are unmasked back to the original spans, and the placeholder multiset, pair order and nesting are validated as a hard gate. |
| Protected content            | Code, math, and technical markup preserved verbatim and never translated (DD-49): inline `<code>` and inline MathML are masked as single atomic placeholders with their text kept exactly; block code listings (`<pre>`/`<pre><code>`, fenced/indented Markdown blocks) and block-level MathML are **non-translatable blocks** — they yield no segments, are excluded from segmentation and the chunk token budget, and live only in the skeleton. Index-term/cross-reference anchor ids and targets are preserved while their visible link text stays translatable. |
| Round-trip fidelity          | The property that parsing a document to skeleton + segments and reassembling it without changing any target text yields a **structure-and-text-preserving (canonical-equal)** result: structure, nesting, IDs, images, fonts, encoding, and all text are preserved, but exact bytes may differ under re-serialization (modulo intentional language-metadata updates; TXT compares exact bytes). Verified by the round-trip golden test, which compares canonicalized output to canonicalized source (DD-43).                                                         |

## consistency-and-memory-terms {#consistency-and-memory-terms}

| Term                                    | Definition                                                                                                                                                                                                                                                                                                                                                  |
|-----------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Glossary / term dictionary              | The editable table of names and terms with their locked target renderings, type, and grammatical gender. Used to enforce terminology; can hard-lock a term via placeholder substitution. Also called the name/term dictionary.                                                                                                                              |
| Book map                                | The project's glossary and lexicon together: what the book names (people, places, organisations, products, materials, titles, terms), the forms the book writes them in, their renderings and genders, each value with where it came from. |
| Lemma entry                             | A glossary entry kept under a name's base form (the lemma, e.g. `Велемир`) with the inflected forms the book uses (`Велемира`, `Велемиру`) listed as its forms, so an ending never makes a new name. `lemmaInferred` marks a base form inferred from its forms rather than seen in the book. |
| Origin                                  | Where a glossary value (target, type, gender) came from: **user** (the person typed, imported, confirmed or locked it), **book** (the book proved it — a verified reading, a pronoun or past-tense count), **rule** (a rule of the code or a bundled list), **likely** (a guess nobody confirmed). An automatic update never replaces a value of a higher origin and never the person's; the person may always edit any value. Only user and book genders are enforced by the checks. |
| Target state                            | How firmly a glossary target holds: **suggested** (the model's proposal nobody confirmed, a hint only), **pinned** (the stem is fixed, every inflected form of it is allowed), **locked** (the exact text, replaced by a token in the book). |
| Likely value                            | A value the analysis filled that the person has not confirmed (origin **likely**): shown as "likely", offered to the model as a hint, never enforced. |
| Translation memory (TM)                 | A store of previously translated segments keyed by source and surrounding context, reused to keep repeated content consistent. Match tiers: **exact** (identical source — a hint, not a force), **context** (source and neighbouring segments both match — eligible for automatic reuse), **fuzzy** (near-identical source — offered as a suggestion only). |
| Rolling summary                         | A running bilingual summary of the book so far, updated at the end of each chapter/unit and injected into later prompts to preserve plot, tone, and terminology context without resending the whole book.                                                                                                                                                   |
| Deferred resolution / backward revision | A register of decisions that cannot be settled with only the text seen so far (e.g. a name whose gender is revealed later). Deferred items are resolved in an optional backward-revision pass using whole-book facts, re-rendering affected earlier segments to `REVISED`.                                                                                  |
| Quality dial                            | A single "quality vs speed" control (Fast / Balanced / Max) that owns **mechanics only**: preceding-target block count, the fixing call (one repair, or Fast's marks-only re-draft), how many reviewer passes read a chunk (0 / 1 / 2) and whether backward revision runs. The batch size is the model profile's, not the dial's. It never sets the trust threshold τ (DD-45).                                                                                               |
| Review-mode dial                        | The Unattended / Assisted / Manual review control. It is the **sole owner of the trust threshold τ**; a manual Settings τ is an advanced override of highest precedence (DD-45).                                                                                                                                                                            |
| Trust threshold τ                       | Retired by 15d.6: acceptance no longer compares a confidence with a threshold. Acceptance = hard gates pass ∧ no deterministic check blocks ∧ no verified reviewer blocker is left; a segment that fails gets the one repair and, if a BLOCK finding is still left, is flagged. The review mode decides only when the run pauses.  |

## pipeline-quality-terms {#pipeline-quality-terms}

| Term          | Definition                                                                                                                                                                                                                                                                                                                               |
|---------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| InferenceGate | The single-flight guard that serializes inference requests so a local model serves one request at a time, preventing concurrent calls from overloading a single-GPU backend.                                                                                                                                                             |
| Reviewer      | The LLM step, per chunk and pass, that reads source and candidate pairs and answers per segment `ok`, find-and-replace edits `{criterion, quote, replacement}` or a rewrite; the application verifies every edit in code before applying it. Fluency and style remarks are notes. Replaces the judge (15d.6). |
| Judge         | Replaced by the Reviewer (15d.6). The step that read a draft that had passed the deterministic checks and returned a score; it flagged faithful text for nothing on a real book and could not name the wrong word.                                                                                                              |
| Self-heal     | The repair stage that fires only on a quality failure. Since redesign group 10 it is **one repair**: a single call (`REPAIR`) that repeats the draft's request with the previous attempt and every BLOCK and REPAIR defect, kept only if `NeverWorse` says the text is not worse; Fast re-drafts once only when formatting marks are lost. The **directed fix** remains only for a reviewer edit the checks refused, until group 14. The reflect → improve chain and the repair rounds are gone. |

## provider-terms {#provider-terms}

| Term                                   | Definition                                                                                                                                                                                                                                                  |
|----------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Provider                               | A configured LLM backend the user can translate against. Modelled as a `ChatModel` port with two client implementations selected by kind — an Ollama-native client and an OpenAI-compatible client — plus a `ProviderConfig` that also holds the detected server engine (DD-10, DD-32, ADR-0047). |
| Provider profile                       | The per-kind data record (endpoint shape, auth scheme, discovery method, capability quirks) for a provider kind, selected by a factory map.                                                                                                                 |
| Model profile                          | How requests to one model are shaped: its thinking switch (none, on/off, levels, always, unknown, or on and not switchable), where the system text goes, the template quirks a request works around, the samplers, the window facts, the answer cap and the batch size. It is resolved at every call from the server engine, the server's facts about the model (which win over a row), the built-in row its name picks, and the person's Thinking and Sampling overrides on Settings › Models (which win over everything); a model no row knows gets the safe default profile (no thinking control, answers asked through the prompt, BookLoom's temperatures, a batch of 2, verdict "unknown model"). Never stored; what a person reads about the model is the model report (design D20 of `redesign-translation-pipeline`). |
| Server engine                          | The program that answers at a provider's address: Ollama, LM Studio, llama-server (llama.cpp), OpenRouter, Unsloth, or a generic OpenAI-compatible server. It is detected from the shape of the server's reply bodies when the person saves or tests the provider or presses Detect again (never by port or status), stored on the provider, and selects request fields, error rows and routes; the provider kind stays the transport (ADR-0047). |
| Treat this server as…                  | The person's choice of server engine on Settings › Providers. It wins over detection until Detect again clears it, and detection never overwrites it.                                                                                                       |
| Ollama / LM Studio / OpenAI-compatible | Supported provider kinds and presets. Ollama and LM Studio are local runtimes exposing OpenAI-compatible chat plus native endpoints; "OpenAI-compatible" is any endpoint speaking the OpenAI chat schema (llama-server, Unsloth and generic servers are of this kind, with their own engine).                                                               |
| num_ctx                                | The model context-window size (in tokens). Ollama honours it reliably only on its native API, which is why Ollama uses the dedicated Ollama-native client (setting `num_ctx` via native `options`) rather than the OpenAI-compatible client (DD-10, DD-32). |

## format-terms {#format-terms}

| Term  | Definition                                                                                                                                        |
|-------|-----------------------------------------------------------------------------------------------------------------------------------------------------|
| EPUB  | A ZIP-packaged XHTML e-book format (versions 2 and 3 supported). Contains an OPF package document, a spine, content documents, images, and fonts. |
| FB2   | FictionBook 2 — a single XML document (optionally zipped as `.fb2.zip`) with embedded binary images, structured verse, and metadata sections.     |
| OPF   | The Open Packaging Format package document inside an EPUB: it declares metadata, the manifest of resources, and the spine.                        |
| Spine | The ordered list in the OPF that defines the linear reading order of an EPUB's content documents.                                                 |

## error-and-envelope-terms {#error-and-envelope-terms}

| Term                       | Definition                                                                                                                                                                                                         |
|----------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Result / AppError envelope | The uniform return shape `Result{data, error}` used across services; failures carry one typed `AppError` with an `ErrorCode` and a safe-details allowlist, enabling partial results. Defined in the `:api` module. |
| Round-trip golden test     | The automated test that asserts round-trip fidelity for representative documents of each supported format.                                                                                                         |
