Every task is self-contained: its **Read** list names what it needs, its **Depends on** line names what must
already exist, and its **Excludes** line names the nearby work that belongs to a different task — so it can be
planned and applied in a session that remembers nothing about the others. These rules apply to every task:

- **Git.** Work on `feature/add-ui-translation-workspace--<task>` (for example `--1.1-token-catalogue`), commit
  there, squash-merge one commit into `feature/add-ui-translation-workspace`, and delete the task branch
  (`AGENTS.md#git`).
- **Tests first.** Write the task's tests, run them and watch them fail, then implement
  (`AGENTS.md#definition-of-done`). Name tests `method_state_expected`, put no `if`, `for` or `while` in a test
  body (use `@ParameterizedTest`), create files in `@TempDir`, and write expected values out instead of
  recomputing them (`.claude/rules/testing.md`). UI tests run on JavaFX 26's built-in headless platform
  (ADR-0019) — never a real display. "Wired" is asserted behaviourally: drive the state mirror and assert the
  node changed, fire the control and assert a recording fake port was called, never by inspecting a binding.
- **Patterns to copy rather than invent.** TestFX shape: `modules/ui/src/test/java/ua/bookloom/ui/HeadlessToolkitCanaryTest.java`
  and `ThemeTest.java` (both extend `org.testfx.framework.junit5.ApplicationTest`; headlessness comes from
  `bookloom.test-conventions`, not from a per-test flag). Recording fakes:
  `modules/app/src/test/java/ua/bookloom/app/cli/TranslateCommandTestFakes.java` (`RecordingProviderConfigs`,
  `ScriptedProviderVerifier`, `RecordingChatModelFactory`) and
  `modules/pipeline/src/test/java/ua/bookloom/pipeline/TranslationJobTestSupport.java`. WireMock per dialect:
  `modules/llm/src/test/java/ua/bookloom/llm/client/ollama/OllamaClientTest.java` and
  `.../openai/OpenAiCompatibleClientTest.java` — each sets up its own server, and this change adds no shared
  harness.
- **Logging is part of done.** Write what the task's **Log** line lists: INFO for lifecycle, DEBUG for every
  working method's parameters and every branch taken, TRACE for book text, WARN for degraded or refused
  outcomes, and never a credential (`.claude/rules/logging.md`). No log call inside a layout pass, a cell's
  `updateItem`, or a listener on a high-frequency value — that rule is what keeps the progress display from
  writing a line per segment per repaint.
- **Code rules.** `.claude/rules/java-coding-style.md`: records for data, `Objects.requireNonNull` at
  boundaries, a `@NullMarked` `package-info.java` with a purpose Javadoc for each new package, constructor
  injection only with `@RequiredArgsConstructor(onConstructor_ = {@Inject})` on anything Guice constructs
  implicitly, no `synchronized`, methods of at most 30 lines and files of at most 400.
  `.claude/rules/javafx-ui.md`: no scene-graph access off the FX thread, no `node.setStyle(...)`, no hard-coded
  FXML path. `.claude/rules/theming-tokens.md`: no colour value outside a `.root` value block.
  `.claude/rules/error-envelope.md`: every port method returns a `Result` behind a boundary `try/catch`.
- **A new package is not done until JPMS knows about it.** `modules/ui/src/main/java/module-info.java` today
  `exports` and `opens` only `ua.bookloom.ui`. Guice constructs controllers and FXML injects into their fields by
  reflection, so **every new `:ui` package needs its own `opens <package> to javafx.fxml, com.google.guice;`**
  line in the same task that creates it. A missing `opens` compiles, passes every test that runs on the
  classpath, and fails only in the packaged image (`AGENTS.md#what-will-bite-you`) — which is why task 10.1 runs
  the packaging scripts rather than trusting `./gradlew :app:run`, whose own build file records that a classpath
  launch cannot see a JPMS fault.
- **Finish** with `./gradlew spotlessApply`, then the task's **Done when** commands.
- **Sources.** Requirements are named in quotes and live in this change's `specs/<capability>/spec.md` — note
  that a screen's requirements live under the capability whose behaviour it surfaces, not under `app-shell`.
  Decisions are in `design.md` (D1–D13). The visual reference is `docs/specification/mockups/ui-mockup.html`,
  which is the only authority for which regions are disabled; each delta spec also enumerates them in words.
