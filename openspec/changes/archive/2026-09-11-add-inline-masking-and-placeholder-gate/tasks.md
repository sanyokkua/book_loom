## 4. Mask non-translatable content a book has nested inside prose

- [x] 4.1 Mask a `<pre>` listing or a block-level `<math>` occurring among a text-owning block's children as a protected span, and make its restored form identical to its source form. The frozen rule that a code listing "is never a segment, it lives in the skeleton alone" is written for a listing that stands on its own; one nested inside a text-owning block has no such option, and leaving it unmasked hands raw `<pre>` markup to the model inside the prose. → `:document` · `document-round-trip/spec.md#requirement-mask-a-non-translatable-block-that-a-book-has-nested-inside-a-translatable-one`, ADR-0031
- [x] 4.2 Prepend a line feed when capturing a nested listing whose first text child begins with one, **on the EPUB adapter only**, so a listing captured and re-parsed does not lose a line on every cycle. The HTML parser discards one line feed after a `<pre>` start tag and the writer's document-wide restorer puts exactly one back at serialization — but a nested fragment goes through a *second* parse and loses a second, which the restorer cannot see. The XML parser discards nothing, so applying the same prepend to FB2 would *add* a line on every cycle. → `:document` · same requirement, `openspec/specs/document-round-trip/spec.md#requirement-preserve-the-leading-line-break-of-a-preformatted-block`
- [x] 4.3 Add tests marked `// Covers: FR-DOC-04, EC-CODE-4 — WHEN a non-translatable block occurs inside a translatable run, the system SHALL mask it as a protected span and restore it identically` for a `<pre>` nested in a text-owning `<div>`, a block-level `<math>` nested in a paragraph, a nested listing whose content begins with two line feeds, and an FB2 `<pre>`-shaped nesting that must **not** gain a line feed. Write the fixtures with a `<div>` and not a `<p>`: an HTML parser closes an open paragraph at a `<pre>` start tag, so the `<p>` shape produces a sibling and the test would assert nothing. → `:document` · same requirement
- [x] 4.4 Stop descending into an inline code span in `BlockSegmentWalker` **for XHTML only**, so an XHTML block whose only translatable content is one yields no segment. FictionBook uses the same element name for an ordinary prose style, where a paragraph written entirely in it is real text a reader reads; excluding it there would silently drop content. Today the paragraph owns no direct text, so the structural rule descends into the code span and makes it the segment — handing the model an identifier to translate, which DD-49 forbids and which this change's own atomic-code requirement would otherwise ship contradicted by the code. The exclusion is consulted before descending and never by run emission, so a code span inside a text-owning block is still masked. Measured, no existing fixture's segment count or kinds move, because every `<code>` in the fixture tree already sits inside a `<pre>`. → `:document` · `document-round-trip/spec.md#requirement-exclude-non-translatable-blocks-from-segmentation`, design.md D11
- [x] 4.5 Add tests marked `// Covers: FR-DOC-04, FR-DOC-EPUB-9 — IF an XHTML block's only translatable content is an inline code span, THEN the system SHALL produce no segment for it and preserve it through the skeleton alone` for a code-only paragraph yielding no segment, that span surviving a zero-edit round trip, a code span inside prose still being a segment's content, and an FB2 paragraph written entirely in `<code>` still being a segment. → `:document` · same requirement
- [x] 4.6 Exclude from the text-coverage denominator the text of exactly those blocks that now yield no segment — per block, never a blanket removal of every `<code>` element, because a code span inside prose is still inside a segment and still belongs in both sides of the ratio — and re-derive every affected fixture floor. The measurement already removes `pre` and `math` and counts an inline code span as translatable because it "sits inside a segment" — which stops being true for a code-only block, so leaving it in the denominator would report a shortfall the parser did not cause and drag every technical book's measured coverage down. → `:document` · `document-round-trip/spec.md#requirement-prove-that-segmentation-covers-the-documents-translatable-text`
- [x] 4.7 Add a test marked `// Covers: FR-DOC-01 — WHEN coverage is measured, the system SHALL count text inside deliberately excluded blocks and protected spans as not translatable on both sides of the ratio` asserting that a `<pre><code>` listing's text and a code-only block's text appear in neither the segments nor the source total, and that every declared floor stays within `0.02` of what is measured. → `:document` · same requirement

## 6. Mask a Markdown segment, and a plain-text one

- [x] 6.1 Implement Markdown masking against the inline source spans the reader already collects, taking each construct's first span's start and last span's end, because an emphasis spanning a line break reports two disjoint spans. Mask an emphasis, a strong emphasis and a link whose visible text is not its own destination as a paired group; mask a code span, an image, and each inline HTML fragment as one atomic token; mask any other inline construct atomically, so enabling a Markdown extension later cannot leave a new construct unmasked. Take the source substring, never the parser's literal, which has already un-escaped `\*` and `&amp;` and would write a re-spelled document back into the byte buffer. → `:document` · `document-round-trip/spec.md#requirement-mask-a-markdown-segment-by-the-source-ranges-of-its-inline-constructs`, design.md D7
- [x] 6.2 Mask a link atomically when its source substring is delimited by `<` and `>`, or when its sole text child's literal equals its destination. Destination-equality alone is not enough: an email autolink `<me@example.com>` has the destination `mailto:me@example.com` and the text `me@example.com`, so an equality test pairs it and hands the address to the model as prose — the one thing the requirement to protect URLs forbids. → `:document` · same requirement, FR-DOC-10
- [x] 6.3 Mask a hard line break by deriving its range from the end of the preceding text run, because the parser reports no span for the two-trailing-spaces form and folds the spaces into the preceding text node instead — the range is that node's *last* source span read back out of the raw source text, with its trailing spaces stripped, or the single backslash for the other spelling. (This supersedes an earlier, wrong statement of the formula as "that node's span end minus its literal length": measured against the pinned commonmark, the literal occupies the span's head rather than its tail, its length diverges from the span's whenever the text holds a backslash escape or a character reference, and for the spacer node commonmark actually emits — span length 2, literal length 0 — it yields an empty range.) Masking it is what gives the model a token to preserve and turns its loss into a failure the repair tier can name; leaving it unmasked would produce a chunk failure with nothing in the report to explain it. → `:document` · same requirement, design.md D7
- [x] 6.4 Leave the residual Markdown source text exactly as written — no decoding of backslash escapes, no expansion of character references — because Markdown reassembly is a byte splice into the original buffer and any re-spelling changes what the next parse sees. This is the one place the masked form is *not* decoded, and the contrast with EPUB and FB2 is deliberate. → `:document` · `document-round-trip/spec.md#requirement-present-a-buffer-shaped-segments-masked-form-as-its-own-source-text`, ADR-0031
- [x] 6.5 Populate `masked` and `placeholders` in `TxtReader`. Plain text has no inline markup, so a TXT segment masks to itself with an empty map unless it contains a literal `⟦` or `⟧`, protected by the same rule as every other format. Leaving TXT on the old pass-through would make it the one format whose two fields still mean nothing. → `:document` · `document-round-trip/spec.md#requirement-leave-prose-text-unmasked`, `#requirement-protect-a-placeholder-bracket-that-occurs-in-the-source-text`
- [x] 6.6 Add tests marked `// Covers: FR-DOC-MD-1, EC-MD-1 — WHEN a Markdown block is segmented, the system SHALL replace each inline construct using the source ranges it occupies and leave the remaining source text unaltered` for emphasis, a link whose destination rides in its closing token, an autolinked URL, an autolinked email address, a self-referential link, a code span, an image, an inline HTML start and end tag as two separate tokens, an unpaired `<br>`, a strong emphasis nested in an emphasis, an emphasis spanning a line break, and a hard line break masked as a token whose fragment is its two spaces. → `:document` · `document-round-trip/spec.md#requirement-mask-a-markdown-segment-by-the-source-ranges-of-its-inline-constructs`
- [x] 6.7 Add tests marked `// Covers: FR-DOC-MD-1 — IF a segment's format reassembles by splicing into the original byte buffer, THEN the system SHALL carry its source text exactly as the file spells it` for a Markdown backslash escape and a character reference, and marked `// Covers: FR-DOC-04 — WHILE a plain-text paragraph is masked, the system SHALL leave its masked form equal to its source text with an empty placeholder map` for an ordinary TXT paragraph. → `:document` · `document-round-trip/spec.md#requirement-present-a-buffer-shaped-segments-masked-form-as-its-own-source-text`, `#requirement-leave-prose-text-unmasked`
