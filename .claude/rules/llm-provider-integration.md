# LLM Provider Integration

Scope: `:llm` (`ua.bookloom.llm..`). Spec: `docs/specification/02_Architecture/04_LLM_INTEGRATION.md`. Transport is JDK `java.net.http.HttpClient`; JSON is Jackson over records. FX-free.

## MUST

- **MUST** expose provider access only through the `ChatModel` port + `ChatModelFactory` (`ua.bookloom.api.llm`); the concrete per-dialect client is hidden behind the internal `ProviderClient`/`ProviderClientFactory` seam in `:llm`, and callers never branch on kind. Two implementations exist: an **Ollama-native** client (`/api/chat`, `/api/tags`, `/api/show`, native `options`) for `OLLAMA`, and an **OpenAI-compatible** client (`/v1/chat/completions`, `/v1/models`, `response_format`) for `OPENAI_COMPATIBLE` (LM Studio and any other OpenAI-shaped server). The kind enum (`ProviderKind`) is extensible; a future provider (Gemini/Claude) is a new implementation registered in `ProviderClientFactory` — not implemented here. — Rationale: callers stay dialect-agnostic; the seam is open without speculative code.
- **MUST** provide a dedicated `probe()` on the internal `ProviderClient` seam (Ollama root/`/api/version`; OpenAI-compatible `/v1/models` HEAD/cheap GET) so the **Connection and Models verification stages are separable** (`VerificationStage.CONNECTION`/`MODELS`, `ProviderVerifier`) — a server with no discovery endpoint still passes Connection independently. — Rationale: reachability is provable without listing models or running inference.
- **MUST** keep `chat` **synchronous, returning `Result<ChatResponse>`** (whole body) — there is no `ChatRequest.stream` field and no partial reply reaches a caller. The **Ollama-native client reads its reply as an NDJSON stream internally** (`stream:true`) and assembles the same whole response, so a reply that stops sending is ended by an **idle gap** (60 s, or the configured timeout when shorter) while the whole call stays bound by its per-kind timeout (`RequestTimeouts`); the OpenAI-compatible client stays non-streaming. Cancellation = a cooperative interrupt that ends the wait at once and closes the connection, with the timeouts as the hard bound. — Rationale: callers stay simple, and a stalled model is caught within a minute instead of holding a run for the full timeout.
- **MUST** talk to Ollama through its **native API**, not the OpenAI-compatible shim, so `num_ctx`, `keep_alive`, `format`, and `think` are actually honored — the `/v1/*` surface does not fully apply them. — Rationale: reliable context-window and reasoning/format control for local Ollama models.
- **MUST** run every model-facing response through the JSON-first tolerant pipeline: **always attempt** structured output (OpenAI `response_format` / Ollama `format`), set reasoning low/off where controllable, **sanitize** (strip `<think>` blocks, chain-of-thought preambles, code-fence wrappers, stray prose), **parse tolerantly** (unknown ignored, missing defaulted, trimmed), do **one** repair retry on malformed JSON, then fall back to the sanitized text as the plain translation — flagging only if QA then fails. — Rationale: models wrap/narrate JSON; be strict in the ask, tolerant in the parse.
- **MUST** treat a **structured-output rejection (HTTP 400 / unsupported) as a silent downgrade**: re-issue the call as a plain request and continue down the text-fallback path — never a hard failure — and record the result on a `supportsStructuredOutput` capability that is **populated during the Models/Inference verification stage**. — Rationale: capability is discovered, not assumed; a picky server degrades gracefully.
- **MUST** keep reasoning control **best-effort**: set the reasoning/effort parameter low/off where controllable (Ollama `think:false`; OpenAI-compatible reasoning-effort), **omit it when unsupported**, and always fall through to the `<think>`-strip sanitize path regardless. The Ollama request never reads `/api/show` to inform this. — Rationale: some models can't disable reasoning; the strip path is the guarantee.
- **MUST** order empty responses distinctly: a **raw-empty** (blank *pre-sanitize*) response → `emptyCompletion`; a **non-empty response that sanitizes to empty** → **one repair retry** specific to empty-after-sanitize, then an empty text-fallback result that **QA flags** (not `emptyCompletion`). — Rationale: "model emitted nothing" and "model emitted only reasoning" are different failures.
- **MUST** construct both clients with **one injected `java.net.http.HttpClient`**, a **fresh per-request timeout**, request/response DTOs as **records in an internal `dto` package** (`@JsonInclude(NON_NULL)`), a **tolerant `ObjectMapper`**, and **never log secrets or full book text**. — Rationale: shared transport, no leaked prompts/credentials, no explicit-null rejections.
- **MUST** verify connection + bound-model availability **before ANY inference** (real runs and diagnostics), failing fast with a typed error; a project **reuses its own bound provider/models**, and any fallback to the current default happens **only on user confirmation** — never a silent switch. `current_provider` is the **new-project default only** and is **never consulted for an existing project's run**. — Rationale: no mid-run quality regression from a moved-out-from-under-it provider.
- **MUST** define **"available"** as: with discovery, membership in `listModels()`; without discovery (a manual model ID), the **Inference round-trip is the availability check** (`modelUnavailable` on failure). Preflight the **translator model always**, and the **judge/helper model only when the quality dial will invoke the judge**. — Rationale: availability has no meaning beyond "the list, or a real call"; an unused judge slot needn't be proved.
- **MUST**, on resume, compare the project's `last_used_json` against the **live provider row** and, on **any drift** (not only a settings-default difference), raise the ADR-0012 "apply new vs continue" prompt (default: continue). — Rationale: any silent divergence between snapshot and live config is a surprise the user must confirm.
- **MUST** run a **credential-resolution pre-check** before the Connection probe, mapping a not-yet-resolvable draft credential to `missingCredential` and **failing the Connection stage** — no network round-trip against a missing secret. Diagnostics go through the same **blocking gate** as every other call and simply wait for a call already in flight; a held gate is not surfaced as `busy` here — `busy` exists only for the review-retry case above. — Rationale: a draft with an unresolved secret fails fast and locally.
- **MUST** omit nullable `ChatRequest` parameters from the serialized JSON entirely (Jackson non-null inclusion) rather than sending `null`. — Rationale: some servers reject explicit nulls; absent means "use default".
- **MUST** store credentials **as a reference only** — an env-var name or an OS-keychain handle — and resolve the secret at call time. The secret value is **never** persisted, logged, or placed in an `AppError`. — Rationale: privacy invariant; the app holds a pointer, not the key.
- **MUST** serialize inference through a single-flight `InferenceGate` backed by `Semaphore(1)`; its only entry point, `run`, **blocks** until the permit is free — there is no non-blocking or bounded-wait variant. The gate is **released during backoff / `Retry-After` sleeps and re-acquired per attempt**, so a sleeping call never holds the permit. The one `busy` outcome in this system is a review retry asked while the project's run is RUNNING, refused from the run record before any model call and never queued behind the run. — Rationale: a local model serves one request at a time; the gate prevents overload without starving on sleeps, and the run record — not the gate — is what tells an in-flight run apart from a paused one.
- **MUST** make the **repair retry a fresh call**: it **re-acquires the gate**, gets its **own fresh timeout**, is subject to **transport retry independently**, **does not recurse** into a second repair, and is bounded — together with transport retry — by a **single global attempt cap** (transport-retry × repair can't run away). — Rationale: repair is a re-ask, not a nested loop; one cap keeps total work finite.
- **MUST** own retry inside the service, keyed on **typed retryable** `ErrorCode`s (`timeout`/`rateLimited`/`unreachable`/`upstream`), honouring `Retry-After` and using a **fresh timeout per attempt**; non-retryable codes fail immediately. A `timeout` is retried **at most once, never as the identical request** (a sampling seed and three quarters of any output cap). — Rationale: retries are principled and bounded, not blind.
- **MUST** map every HTTP outcome to a typed `AppError` (`401/403→auth`, `429→rateLimited`, connect-refused→`unreachable`, `5xx→upstream`, unknown model→`modelNotFound`, `200`-but-raw-empty→`emptyCompletion`, over-context→`contextWindow`, discovery failure→`discoveryFailed`, model unavailable at preflight/run→`modelUnavailable`, unresolved credential→`missingCredential`). A structured-output rejection is **not** an error (silent downgrade). — Rationale: callers branch on codes; see `error-envelope.md`.

## SHOULD

- **SHOULD** support the three-stage verification against the **draft** provider config before it is saved: **Connection** via the dedicated `probe()` (separable from listing), **Models** via `listModels()` (`discoveryFailed` on hard failure), **Inference** via a tiny `chat` round-trip that also **populates `supportsStructuredOutput`**. — Rationale: users validate a provider before committing it, and each stage is independently reportable.
- **SHOULD** send this build's **one fixed context of 8192** as the Ollama-native client's `num_ctx`, send no context-size parameter to an OpenAI-compatible server (its shape cannot express one), and resolve no per-provider effective-context value until the Generation settings exist (future work) — the chunk packer budgets against this same fixed 8192. — Rationale: token budgeting needs a real, stated window today; a resolved per-provider value is a later change, not a silent guess in this one.
- **SHOULD** treat **manual model-ID entry as first-class and always available**: when discovery (`ModelCatalog.listModels`) is absent/fails/empty/unauthorized, use free-text model-ID entry (pre-filled with the remembered model). Only translator + judge/helper slots exist — no embedding slot. — Rationale: not every server lists models; consistency comes from dictionary + string-similarity TM + rolling summary, not vectors.
- **SHOULD** keep DTOs as records in a non-exported `dto` package `opens` to Jackson only. — Rationale: wire types stay internal and records-first.

## Reject if

- A caller branches on provider kind or talks to a concrete client directly instead of going through the `ChatModel` port + `ChatModelFactory` (or the internal `ProviderClient`/`ProviderClientFactory` seam within `:llm`).
- Ollama is driven through the OpenAI-compatible `/v1/*` shim instead of its native API, or `num_ctx`/native-only options are forced onto an OpenAI-shaped request instead of the Ollama-native client.
- Model output is parsed strictly (no sanitize / no tolerant parse), repair-retried more than once, the repair recurses into a second repair, or output is hard-failed instead of falling back to the sanitized plain text.
- A structured-output rejection (400/unsupported) is treated as a hard failure instead of a silent downgrade to a plain request + text fallback.
- A `ChatRequest.stream` field or a caller-visible streaming path is introduced, or `chat` is made asynchronous/partial instead of returning the whole `Result<ChatResponse>`; or a streamed Ollama reply is read without an idle-gap bound.
- A non-empty-but-sanitizes-to-empty response is reported as `emptyCompletion` instead of taking its one empty-after-sanitize repair and then flagging via QA.
- The `InferenceGate` is held across a backoff / `Retry-After` sleep instead of being released and re-acquired per attempt.
- The judge/helper model is preflighted when the quality dial will not invoke the judge, or drift between `last_used_json` and the live provider row is applied without the ADR-0012 confirmation prompt.
- `current_provider` is consulted for an existing project's run instead of only as the new-project default.
- Inference runs against a project without preflight-verifying its bound provider/model, or a provider/model is silently switched without user confirmation.
- An embedding model slot, vector store, or vector-based similarity is introduced.
- A secret value is persisted, logged, put in `AppError`, or stored anywhere but as an env-var/keychain reference; or full book text / prompt bodies reach a log.
- Nullable `ChatRequest` params are serialized as explicit `null`.
- Inference runs without acquiring the `InferenceGate`, or a review retry is queued behind a RUNNING run instead of being refused with `busy`.
- Retry fires on a non-retryable code, ignores `Retry-After`, or reuses one deadline across attempts.
- An HTTP status is surfaced raw instead of mapped to an `ErrorCode`.
