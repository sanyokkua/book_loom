# LLM Provider Integration

Scope: `:llm` (`ua.bookloom.llm..`). Spec: `docs/spec_baseline/specification/02_Architecture/04_LLM_INTEGRATION.md`. Transport is JDK `java.net.http.HttpClient`; JSON is Jackson over records. FX-free.

## MUST

- **MUST** expose provider access only through the `ChatModel` port + `ChatModelFactory` (`ua.bookloom.api.llm`); the concrete per-dialect client is hidden behind the internal `ProviderClient`/`ProviderClientFactory` seam in `:llm`, and callers never branch on kind. Two implementations exist: an **Ollama-native** client (`/api/chat`, `/api/tags`, `/api/show`, native `options`) for `OLLAMA`, and an **OpenAI-compatible** client (`/v1/chat/completions`, `/v1/models`, `response_format`) for `OPENAI_COMPATIBLE` (LM Studio and any other OpenAI-shaped server). The kind enum (`ProviderKind`) is the **transport** and stays at two values; the **server engine** (`ServerEngine`: Ollama, LM Studio, llama-server, OpenRouter, Unsloth, generic; ADR-0047) is a detected, stored fact on the provider that selects request fields, error rows and routes inside those two clients — never a third client and never a branch in a caller. A future provider (Gemini/Claude) is a new implementation registered in `ProviderClientFactory` — not implemented here. — Rationale: callers stay dialect-agnostic; the seam is open without speculative code; only fields differ per engine.
- **MUST** detect the engine only when the person saves, tests or presses Detect again (at most 7 body-checked GETs of 2 s, no body, no book text, the key only when the provider has one), by the **shape of the reply bodies** — never by a port or an HTTP status alone (`engine/EngineDetector`) — and compute `EngineTraits` from the effective engine (the person's "Treat this server as…" choice, else the detected one) without any network call. A generic server gets no answer schema and no reasoning control until a stored check verdict shows it honours them. — Rationale: a request is built with no round trip, and a look-alike server is never sent another engine's fields.
- **MUST** provide a dedicated `probe()` on the internal `ProviderClient` seam (Ollama root/`/api/version`; OpenAI-compatible `/v1/models` HEAD/cheap GET) so the **Connection and Models verification stages are separable** (`VerificationStage.CONNECTION`/`MODELS`, `ProviderVerifier`) — a server with no discovery endpoint still passes Connection independently. — Rationale: reachability is provable without listing models or running inference.
- **MUST** keep `chat` **synchronous, returning `Result<ChatResponse>`** (whole body) — there is no `ChatRequest.stream` field and no partial reply reaches a caller. The **Ollama-native client reads its reply as an NDJSON stream internally** (`stream:true`) and assembles the same whole response, so a reply that stops sending is ended by an **idle gap** (60 s, or the configured timeout when shorter) while the whole call stays bound by its per-kind timeout (`RequestTimeouts`); the OpenAI-compatible client stays non-streaming. Cancellation = a cooperative interrupt that ends the wait at once and closes the connection, with the timeouts as the hard bound. — Rationale: callers stay simple, and a stalled model is caught within a minute instead of holding a run for the full timeout.
- **MUST** talk to Ollama through its **native API** (`OLLAMA` kind) by default, so `num_ctx`, `keep_alive`, `format`, and `think` are actually honored — the `/v1/*` surface does not fully apply them. An Ollama that answers behind an `OPENAI_COMPATIBLE` provider is offered the native connection once and is never switched by itself; while it stays on `/v1`, the cap is sent only as `max_tokens`. — Rationale: reliable context-window and reasoning/format control for local Ollama models, with the person's choice respected.
- **MUST** run every model-facing response through the JSON-first tolerant pipeline: **always attempt** structured output (OpenAI `response_format` / Ollama `format`) on the call kind's current rung, send the call kind's reasoning intent as the model's profile maps it, **sanitize** (strip `<think>` blocks, chain-of-thought preambles, code-fence wrappers, stray prose), **parse tolerantly** (unknown ignored, missing defaulted, trimmed), do **one** repair retry on malformed JSON, then fall back to the sanitized text as the plain translation — flagging only if QA then fails. — Rationale: models wrap/narrate JSON; be strict in the ask, tolerant in the parse.
- **MUST** treat a **structured-output rejection (HTTP 400 / unsupported) as a silent downgrade**: re-issue the call on the prompt-only rung (the shape described in the request text) and continue down the text-fallback path — never a hard failure; the step is per (model, call kind), or every kind for a model-wide failure, stored as a `RefusedSetting` with its scope that the person can send again — and record the result on a `supportsStructuredOutput` capability that is **populated during the Models/Inference verification stage**. — Rationale: capability is discovered, not assumed; a picky server degrades gracefully.
- **MUST** decide reasoning **per call kind from the model's profile** (ADR-0047, design D20 of `redesign-translation-pipeline`): the pipeline sends an intent (off for draft, repair, proofread, names and brief), the person's Thinking override may turn it on, and the dialect mapper sends the engine's own field for it (Ollama `think:false`, or the lowest listed level when the model lists no `false`; `reasoning_effort:"none"` on Ollama `/v1`, LM Studio and a proven generic server; llama-server's `enable_thinking` as a JSON boolean in the template kwargs; Unsloth's top-level `enable_thinking`; gpt-oss `"low"` everywhere) — and **never sends a control the model or the engine does not declare**. A model that cannot be switched gets no control and the profile's reasoning reserve on its cap; every reply still goes through the `ReasoningScrubber`. No chat call reads the server's facts: the profile uses the facts read when the person acted (selecting a model, Settings › Models, Test, Start, Continue). — Rationale: one off value for every model sent fields some models misread; the scrubber is the guarantee.
- **MUST** order empty responses distinctly: a **raw-empty** (blank *pre-sanitize*) response → `emptyCompletion`; a **non-empty response that sanitizes to empty** → **one repair retry** specific to empty-after-sanitize, then an empty text-fallback result that **QA flags** (not `emptyCompletion`). — Rationale: "model emitted nothing" and "model emitted only reasoning" are different failures.
- **MUST** construct both clients with **one injected `java.net.http.HttpClient`**, a **fresh per-request timeout**, request/response DTOs as **records in an internal `dto` package** (`@JsonInclude(NON_NULL)`), a **tolerant `ObjectMapper`**, and **never log secrets or full book text**. — Rationale: shared transport, no leaked prompts/credentials, no explicit-null rejections.
- **MUST** verify connection + bound-model availability **before ANY inference** (real runs and diagnostics), failing fast with a typed error; a project **reuses its own bound provider/models**, and any fallback to the current default happens **only on user confirmation** — never a silent switch. `current_provider` is the **new-project default only** and is **never consulted for an existing project's run**. — Rationale: no mid-run quality regression from a moved-out-from-under-it provider.
- **MUST** define **"available"** as: with discovery, membership in `listModels()`; without discovery (a manual model ID), the **Inference round-trip is the availability check** (`modelUnavailable` on failure). Where an engine answers any id with whatever model it has loaded (LM Studio, Unsloth, a llama-server router), the id is also checked against the server's own list at the first chat call of a session per provider and model (`engine/ModelIdCheck`), and a reply naming another model is refused. Preflight the **translator model**, the only model a project binds (there is no judge or helper slot). — Rationale: availability has no meaning beyond "the list, or a real call"; a misspelt id must never be translated by the wrong model.
- **MUST**, on resume, compare the project's `last_used_json` against the **live provider row** and, on **any drift** (not only a settings-default difference), raise the ADR-0012 "apply new vs continue" prompt (default: continue). — Rationale: any silent divergence between snapshot and live config is a surprise the user must confirm.
- **MUST** run a **credential-resolution pre-check** before the Connection probe, mapping a not-yet-resolvable draft credential to `missingCredential` and **failing the Connection stage** — no network round-trip against a missing secret. Diagnostics go through the same **blocking gate** as every other call and simply wait for a call already in flight; a held gate is not surfaced as `busy` here — `busy` exists only for the review-retry case above. — Rationale: a draft with an unresolved secret fails fast and locally.
- **MUST** omit nullable `ChatRequest` parameters from the serialized JSON entirely (Jackson non-null inclusion) rather than sending `null`. — Rationale: some servers reject explicit nulls; absent means "use default".
- **MUST** store credentials **as a reference only** — an env-var name or an OS-keychain handle — and resolve the secret at call time. The secret value is **never** persisted, logged, or placed in an `AppError`. — Rationale: privacy invariant; the app holds a pointer, not the key.
- **MUST** serialize inference through a single-flight `InferenceGate` backed by `Semaphore(1)`; its only entry point, `run`, **blocks** until the permit is free — there is no non-blocking or bounded-wait variant. The gate is **released during backoff / `Retry-After` sleeps and re-acquired per attempt**, so a sleeping call never holds the permit. The one `busy` outcome in this system is a review retry asked while the project's run is RUNNING, refused from the run record before any model call and never queued behind the run. — Rationale: a local model serves one request at a time; the gate prevents overload without starving on sleeps, and the run record — not the gate — is what tells an in-flight run apart from a paused one.
- **MUST** make the **repair retry a fresh call**: it **re-acquires the gate**, gets its **own fresh timeout**, is subject to **transport retry independently**, **does not recurse** into a second repair, and is bounded — together with transport retry — by a **single global attempt cap** (transport-retry × repair can't run away). — Rationale: repair is a re-ask, not a nested loop; one cap keeps total work finite.
- **MUST** own retry inside the service, decided by the **matched catalogue row's `RetryRule`**: `SAME` and `NEW_SEED` resend **once** (`SAME` only after a state check finds the server answering, `NEW_SEED` with another seed), `NONE` and `AUTO_WAIT` are never resent within the call (an `AUTO_WAIT` wait is the run's), and `BACKOFF` — or a failure no row explains — is retried up to the policy's attempt count; for an unmatched failure `ErrorCode.isRetryable()` (`timeout`/`rateLimited`/`unreachable`/`upstream`) stays the fallback, so a non-retryable code fails immediately. Honour `Retry-After` and use a **fresh timeout per attempt**. A `timeout` is retried **at most once, never as the identical request** (a sampling seed and three quarters of any output cap). — Rationale: retries are principled and bounded, not blind; the same words mean the same remedy on every engine.
- **MUST** map every HTTP outcome to a typed `AppError` **by the meaning of the reply's words**, through the one ordered error catalogue (`llm/http/ErrorRows`; `docs/spec_baseline/specification/02_Architecture/04_LLM_INTEGRATION.md#http-error-mapping`): transport failures first (interrupted→`cancelled`, timeout→`timeout`, connect-refused/I-O→`unreachable`), then the first row whose words the body holds, in any order and whatever the status (a row may be limited to a set of engines, matched against the provider's effective engine), which sets the code, a `FailureReason` token (`reason=<token>` in the safe details) and a `RetryRule`; only a reply no row explains falls to the status alone (`401/403→auth`, `404` on chat→`modelNotFound`, `429→rateLimited`, `5xx→upstream`, `400/422→validation`, else `internal`) with the reason `unclassified`. Also: `200`-but-raw-empty→`emptyCompletion`, discovery failure→`discoveryFailed`, model unavailable at preflight/run→`modelUnavailable`, unresolved credential→`missingCredential`. Never classify by status alone when a row explains the body, and never put the provider's sentence in the details (TRACE only). Every WARN line about a retried, given-up or refused call carries `reason=<token>` from `FailureReason.tokenIn(details)`. A structured-output rejection is **not** an error (silent downgrade). — Rationale: the same words mean the same thing on every engine, so the run acts on what failed, not on a status one engine uses differently; see `error-envelope.md`.

## SHOULD

- **SHOULD** support the three-stage verification against the **draft** provider config before it is saved: **Connection** via the dedicated `probe()` (separable from listing; it also runs engine detection and refuses an app that cannot translate a book), **Models** via `listModels()` (`discoveryFailed` on hard failure), **Inference** via a tiny `chat` round-trip that also **populates `supportsStructuredOutput`**; an optional fourth **Advanced features** stage, started only by the person, stores the verdicts of up to four short checks on the model. — Rationale: users validate a provider before committing it, and each stage is independently reportable.
- **SHOULD** size a run for the model's detected window limited to 16384 tokens (16384 when unknown) unless the person set a context window for that model, which replaces it; send it as the Ollama-native client's `num_ctx`, send no context-size parameter to an OpenAI-compatible server (its shape cannot express one), and read the override again as each chunk is entered (a save applies from the next chunk); the chunk packer budgets against that same window. — Rationale: token budgeting needs a real, stated window, and a person who knows their model's window can set it.
- **SHOULD** treat **manual model-ID entry as first-class and always available**: when discovery (`ModelCatalog.listModels`) is absent/fails/empty/unauthorized, use free-text model-ID entry (pre-filled with the remembered model). Only the translator slot exists — no judge, helper or embedding slot. — Rationale: not every server lists models; consistency comes from dictionary + string-similarity TM + chapter summaries, not vectors.
- **SHOULD** keep DTOs as records in a non-exported `dto` package `opens` to Jackson only. — Rationale: wire types stay internal and records-first.

## Reject if

- A caller branches on provider kind or talks to a concrete client directly instead of going through the `ChatModel` port + `ChatModelFactory` (or the internal `ProviderClient`/`ProviderClientFactory` seam within `:llm`).
- A third client or a per-engine client is added for an engine instead of selecting fields from `EngineTraits`, or an engine is detected by a port or an HTTP status, or at start-up or in the background, or detected engine data is persisted as traits instead of computed.
- A provider the person created as Ollama-native is driven through the OpenAI-compatible `/v1/*` shim, an OpenAI-compatible provider is switched to the native connection without the person's answer, or `num_ctx`/native-only options are forced onto an OpenAI-shaped request instead of the Ollama-native client.
- Model output is parsed strictly (no sanitize / no tolerant parse), repair-retried more than once, the repair recurses into a second repair, or output is hard-failed instead of falling back to the sanitized plain text.
- A structured-output rejection (400/unsupported) is treated as a hard failure instead of a step down to the prompt-only rung (per model and call kind, stored as a refused setting) and the text fallback.
- A reasoning level is sent as one global value, or a reasoning control is sent that the model or the engine does not declare, instead of the call kind's intent mapped through the model's profile.
- A `ChatRequest.stream` field or a caller-visible streaming path is introduced, or `chat` is made asynchronous/partial instead of returning the whole `Result<ChatResponse>`; or a streamed Ollama reply is read without an idle-gap bound.
- A non-empty-but-sanitizes-to-empty response is reported as `emptyCompletion` instead of taking its one empty-after-sanitize repair and then flagging via QA.
- The `InferenceGate` is held across a backoff / `Retry-After` sleep instead of being released and re-acquired per attempt.
- A judge or helper model slot is added, or drift between `last_used_json` and the live provider row is applied without the ADR-0012 confirmation prompt.
- `current_provider` is consulted for an existing project's run instead of only as the new-project default.
- Inference runs against a project without preflight-verifying its bound provider/model, or a provider/model is silently switched without user confirmation.
- An embedding model slot, vector store, or vector-based similarity is introduced.
- A secret value is persisted, logged, put in `AppError`, or stored anywhere but as an env-var/keychain reference; or full book text / prompt bodies reach a log.
- Nullable `ChatRequest` params are serialized as explicit `null`.
- Inference runs without acquiring the `InferenceGate`, or a review retry is queued behind a RUNNING run instead of being refused with `busy`.
- Retry fires on a non-retryable code, ignores `Retry-After`, or reuses one deadline across attempts.
- An HTTP status is surfaced raw instead of mapped to an `ErrorCode`.
