# Java Coding Style

Scope: all Java source (`**/src/main/java/**`, `**/src/test/java/**`) across every module. Java 25 language level. Formatting is enforced separately by Spotless (`gradle-build-and-quality.md`); this rule governs design idioms.

## MUST

- **MUST** model immutable data carriers (DTOs, value objects, wire types) as `record`s — never Lombok `@Data`/`@Value`. On **service/component classes** Lombok is allowed to remove boilerplate: `@RequiredArgsConstructor` (constructor injection of `final` deps), `@Slf4j` (logger), and `@Builder` where a builder genuinely helps. — Rationale: records give immutability, value semantics, and pattern-matching for data; Lombok removes constructor/logger boilerplate on services (DD-05, ADR-0014).
- **MUST** use `Optional<T>` for return values only — never as a field, parameter, or collection element. Use `@Nullable` (JSpecify) at boundaries where absence is expressed instead. — Rationale: `Optional` communicates "no result" at a call site without polluting state.
- **MUST** call `Objects.requireNonNull(x, "x")` for every non-`@Nullable` reference parameter of a public/boundary method (constructors, port impls). — Rationale: fail fast at the boundary, never propagate a silent null inward.
- **MUST** model closed hierarchies as `sealed` types and branch on them with an exhaustive pattern-matching `switch` (no `default` when the compiler can prove exhaustiveness). — Rationale: the compiler flags every unhandled case when a variant is added.
- **MUST NOT** declare or propagate checked exceptions in application code. Wrap I/O/library checked exceptions at the adapter boundary into a `Result.err(AppError(...))`, preserving the original as `cause`. — Rationale: failures cross module edges as the typed envelope, not as `throws`.
- **MUST NOT** use `synchronized` (methods or blocks) in new code. Use immutability, confinement to one thread, `java.util.concurrent` types, or the `InferenceGate` semaphore instead. — Rationale: coarse locks cause contention and deadlocks; see `threading-concurrency.md`.
- **MUST** use constructor injection only (Guice) — no field/setter injection, no static singletons, no service locator. A service Guice constructs via a JIT/implicit binding MUST give `@RequiredArgsConstructor` an explicit `onConstructor_ = {@Inject}` (i.e. `@RequiredArgsConstructor(onConstructor_ = {@Inject})`): Guice only performs implicit constructor injection when a class has either an `@Inject`-annotated constructor or a no-arg constructor, and a bare Lombok `@RequiredArgsConstructor` gives it neither. Use a Guice `@Provides` method instead of constructor injection only when construction needs real logic beyond field assignment. Disambiguate two bindings of the same interface type with a custom `@jakarta.inject.Qualifier` annotation, never by injecting a concrete type. Bind an expensive or effectively-stateful third-party object (a parser/client with internal caches) as a Guice singleton rather than constructing it ad hoc at each use site. — Rationale: dependencies are explicit, final, and testable; the `@Inject` requirement is the difference between a service Guice can actually construct and one that fails at injector-build time.
- **MUST** declare fields, parameters, and locals `final` by default; drop `final` only where reassignment is genuinely required. — Rationale: immutability is the default, mutation is a deliberate exception.
- **MUST** obtain a logger via Lombok `@Slf4j` on every class — never a hand-written `private static final Logger log = LoggerFactory.getLogger(X.class)` field. The only exemption is the bootstrap-path classes named in `logging.md`'s ArchUnit `bootstrap-no-static-logger` rule (`ua.bookloom.app.bootstrap`, `ua.bookloom.util.paths`), which obtain a logger via a local, non-static `LoggerFactory.getLogger(...)` call only after the log directory is published — never a class-init-time field there either. — Rationale: `@Slf4j` generates the exact same field for free everywhere it is safe to have one; see `logging.md`.
- **MUST** hold any data an enum constant carries beyond its own identity (a token, separator, wire string, label) in a **constructor-injected `private final` field with an accessor** — never as parallel static constants matched by string/equality comparison (`OsFamily(char separator)` is the pattern to follow; `AppEnvironment`'s `DEV_TOKEN`/`PROD_TOKEN` matched via `equalsIgnoreCase` is the anti-pattern this replaces). Enum constants MUST be `UPPER_SNAKE_CASE`, with exactly one documented exception: a constant name that **is itself** the literal external wire-format vocabulary term (e.g. `ErrorCode.auth`, `ErrorCode.rateLimited` — the constant name is the spec-fixed wire string, not a Java identifier choice) — such a case needs an inline Javadoc note explaining why, and must never be cited as precedent for inventing another lowerCamelCase constant instead of adding a field. — Rationale: per-constant data belongs in the type system, not in a second lookup table the compiler cannot check; the one legitimate exception is named so it cannot silently spread.
- **MUST** use Lombok `@NoArgsConstructor(access = AccessLevel.PRIVATE)` on static-utility/no-instantiation classes (no state, no injection, every member `static`) instead of a hand-written `private Foo() { /* no instances */ }` constructor (ADR-0024). — Rationale: the same boilerplate ADR-0014 removed from services with `@RequiredArgsConstructor`, removed here for the one other repeating shape.
- **MUST NOT** add a guard/validation for a state the preceding code in the same method or call chain has already made impossible (e.g. re-checking non-null immediately after a compact record constructor already enforced it). **MUST** keep a guard that protects a genuinely reachable state reached from a *different* call path or timing window (e.g. a static holder read before it is ever written, a method callable both before and after some initialization step) — judge this from the actual data flow of the specific code, never from "this looks like a null-check idiom, therefore dead." — Rationale: a redundant guard hides the real invariant under noise; deleting a live one turns a caught bug into a runtime crash.
- **MUST** write a Javadoc comment only to explain **why** something exists or a non-obvious constraint — never to restate what the signature already says. Every `{@link}`/`{@linkplain}` reference MUST resolve to a real, compilable symbol visible from the referencing compilation unit (the same module's exported package, or a package actually on that unit's path) — never a placeholder name or a type that only exists in an unrelated source set. — Rationale: a Javadoc that repeats the signature is noise a reader has to read anyway; a dead `{@link}` fails silently until someone notices the rendered docs are broken.
- **MUST** follow this structural layer on top of the WHY-focused rule above — the mechanics of *where* a constraint goes, not a license to restate the obvious: every package has a `package-info.java` carrying a Javadoc block stating the package's purpose (the file already exists for `@NullMarked`; this adds the doc-comment requirement to it). No `@author` (Git history is authoritative) and no `@since` (application code has no versioned public API). Tag order when present: `@param` (declaration order) → `@return` → `@throws` (by likelihood) → `@see` → `@deprecated`. `@param` states nullability/range/valid-value constraints — the non-obvious constraint a call site can't see from the signature alone — never restates the parameter name. `@return` covers both the success and the empty/failure case, shaped by the return type: `Optional<T>` → "the X if found, or empty if not found"; a collection → "never null; empty if none found"; `boolean` → "`{@code true}` if X, `{@code false}` otherwise". A record documents its components via `@param` tags on the class-level Javadoc. An enum constant that carries data (the constructor-injected-field rule above) gets its own short Javadoc explaining its business meaning, not just its field. An overriding method never duplicates the parent's Javadoc — use `{@inheritDoc}` or omit entirely. Use `{@link}` rather than a plain-text class/method name whenever Javadoc refers to a symbol. — Rationale: documenting nullability/range/failure-shape at the call site *is* the non-obvious constraint the WHY-focused rule already asks for; this bullet is the mechanical checklist for expressing it consistently, not a second, conflicting Javadoc philosophy.
- **MUST** format a `TODO`/`FIXME`/`HACK` comment as `// TODO(owner): description [TICKET-ID]` (same shape for `FIXME`/`HACK`). `FIXME`/`HACK` never exists without a linked ticket ID. A `TODO` with no ticket is resolved or ticketed within 30 days. — Rationale: an untracked TODO is a silent, unbounded liability; the owner and ticket make it someone's job.
- **MUST** use `java.time.*`, never `java.util.Date`/`Calendar`; use `java.nio.file.Path`/`Files`, never `java.io.File`, in new code. A non-deterministic call (`UUID.randomUUID()`, `System.currentTimeMillis()`, `new Random()`) sits behind an injectable seam, not called directly from logic that needs to be deterministically testable. No magic numbers — extract to a named constant. Boolean accessors are prefixed `is`/`has`/`can`. A stream pipeline longer than ~5 chained intermediate operations gets extracted to a named method. — Rationale: modern, testable, self-documenting idioms; the legacy date/file APIs and unseamed non-determinism are the recurring source of untestable code.

## SHOULD

- **SHOULD** keep methods ≤ 30 lines, classes ≤ ~400 lines, and nesting depth ≤ 3. Extract helpers or types past those limits. — Rationale: small units stay reviewable and testable.
- **SHOULD** name by convention: `PascalCase` types, `camelCase` methods/fields, `UPPER_SNAKE` constants, port impls `XxxService`/`XxxImpl`, DAOs `XxxDao`, Guice modules `XxxModule`. — Rationale: predictable names aid ArchUnit rules and navigation.
- **SHOULD** prefer expressions (switch expressions, streams for transformation) over statement-heavy loops when it reduces mutable state — but keep hot paths simple. — Rationale: fewer moving parts, clearer intent.
- **SHOULD** annotate every package `@NullMarked` (JSpecify, package-info) so NullAway treats unannotated references as non-null. — Rationale: null-correctness is checked at compile time.
- **SHOULD** prefer the modern Java idiom available at the project's Java 25 language level over an older equivalent, where it does not hurt clarity: the diamond operator including on anonymous-class instantiations (legal since Java 9 — `new ArchCondition<>("...") { ... }`, not `new ArchCondition<String>("...") { ... }`), pattern-matching `instanceof`/`switch`, text blocks for multi-line string literals, and `var` for a local whose type is obvious from the initializer. — Rationale: the language level is already paid for; using it consistently keeps the codebase from reading like several different Java eras stitched together.

## Reject if

- A data carrier uses Lombok `@Data`/`@Value` instead of a record (Lombok on services is fine: `@RequiredArgsConstructor`/`@Slf4j`/`@Builder`).
- `Optional` appears as a field, parameter, or collection element.
- A public/boundary method omits `requireNonNull` on a non-nullable reference parameter.
- A closed hierarchy is branched with `instanceof` chains or a non-exhaustive switch instead of a sealed type.
- Application code declares `throws` of a checked exception, or swallows a cause when wrapping.
- New code introduces `synchronized`, field/setter injection, or a mutable static singleton.
- A method exceeds ~30 lines, a class ~400 lines, or nesting exceeds 3 with no extraction and no justification.
- A class hand-writes a `LoggerFactory.getLogger(...)` field instead of `@Slf4j`, outside the bootstrap-path exemption named in `logging.md`.
- An enum smuggles per-constant data through parallel static constants matched by equality instead of a constructor-injected field, or a new lowerCamelCase enum constant is added without the documented wire-vocabulary exception.
- A static-utility/no-instantiation class hand-writes its private constructor instead of `@NoArgsConstructor(access = AccessLevel.PRIVATE)` (ADR-0024).
- A guard is added or removed without tracing the actual reachability of the state it checks — either a dead re-check is left in place, or a guard protecting a genuinely reachable state is deleted.
- A Javadoc restates what the signature already says instead of explaining why, or contains a `{@link}` that does not resolve to a real, compilable symbol.
- A Guice-constructed service's `@RequiredArgsConstructor` has no `onConstructor_ = {@Inject}` and no no-arg constructor.
- A `package-info.java` lacks a Javadoc purpose statement, or `@author`/`@since` appears in application Javadoc.
- A `FIXME`/`HACK` has no ticket, or a `TODO` has aged past 30 days with no ticket.
- `java.util.Date`/`Calendar`/`java.io.File` appears in new code, or a non-deterministic call (`UUID.randomUUID()`, `System.currentTimeMillis()`, `new Random()`) is made directly from logic that needs deterministic tests instead of sitting behind an injectable seam.
- A magic number appears without a named constant.
